# أطلس المعرفة | Knowledge Atlas

تطبيق Android عربي أولاً، مصمم ليكون منصة اكتشاف معرفة ومصادر قابلة للتوسع، مع فصل تطبيق الهاتف عن خدمات البحث والمزامنة والتحديث.

## تجربة الواجهة والرؤية البصرية

اتجاه الواجهة هو تصميم عربي RTL بطابع مستقبلي هادئ:
- لوحة ألوان داكنة متعددة الطبقات مع تدرجات لونية وتباين واضح.
- رأس رئيسي متحرك زمنياً، وبطاقات مصادر ذات عمق بصري وحالات تفاعل.
- انتقالات AnimatedContent بين الاكتشاف والمحفوظات والتحديثات.
- بحث وفلاتر المجالات، بطاقات تفاصيل، وحفظ المصادر محلياً.
- تقليل المؤثرات الثقيلة لصالح سلاسة الأداء على هواتف Android المتوسطة.

ملاحظة اصطلاحية: النانومتر وحدة قياس طول تُستخدم في وصف عمليات تصنيع الشرائح والمواد، وليست تقنية واجهات. أما "البعد الرابع" في تجربة الاستخدام فتمت ترجمته إلى بُعد الزمن: الحركة، الانتقالات، وتغيّر حالات الواجهة استجابةً لتفاعل المستخدم. لا يعني ذلك وجود شاشة رباعية الأبعاد أو تقنية عرض مادية جديدة.

## الحالة الحالية

هذا الفرع هو **مرحلة تأسيس تقنية أولى** وليس إصداراً نهائياً:
- مشروع Android/Kotlin مع Jetpack Compose وRoom.
- واجهة عربية RTL مطوّرة بطابع مستقبلي، انتقالات زمنية، تبويب اكتشاف/محفوظات/تحديثات، تفاصيل المصادر، وحفظ المفضلة.
- طبقة اتصال محايدة لمحرك بحث ويب موصولة بالواجهة؛ الخدمة المنشورة تستخدم SearXNG وتوسعة/ترتيباً نصياً أولياً. لم يكتمل بعد بحث embeddings/vector retrieval أو الفهم الدلالي العصبي.
- مدير تحديث مباشر لتوزيعة APK المستقلة، مع HTTPS وفحص SHA-256، ثم تسليم التثبيت إلى Android ليطلب موافقة المستخدم.
- نسختا توزيع منفصلتان: `direct` للتوزيع المباشر و`play` مع تعطيل آلية التحديث الذاتي.
- خدمة البحث الخلفية منشورة على Railway، وتم اجتياز اختبار بحث عربي حي من CI. خادم SearXNG خاص خلف API، وخدمات API وSearXNG وValkey تعمل. لا توجد خدمة كتالوج مستقلة حتى الآن، ولا مفتاح توقيع Release محفوظ في المستودع.

## بنية النظام المستهدفة

1. **Android Client**: واجهة Compose، قاعدة Room محلية، مفضلة وملاحظات، وتجربة Offline.
2. **Knowledge API**: كتالوج المصادر، مزامنة البيانات، التصنيفات، وبيانات التحقق.
3. **Search API**: فهم الاستعلام العربي/الإنجليزي، توسيع المرادفات، البحث الهجين، إعادة ترتيب النتائج، وإرجاع أدلة المصدر.
4. **Update endpoint**: بيان إصدار HTTPS وملف APK موقع بنفس شهادة الإصدار السابق.
5. **Desktop client لاحقاً**: يتصل بنفس خدمات API دون إعادة بناء منطق المعرفة.

## إعداد بيئة البناء

المتطلبات: JDK 17، Android SDK API 36، Gradle 9.4.1.

من مجلد المشروع، بعد توفير Gradle Wrapper scripts وملف wrapper JAR أو تثبيت Gradle محلياً (GitHub Actions يثبت Gradle وAndroid SDK أثناء CI):
```bash
gradle assembleDirectDebug
gradle testDirectDebugUnitTest
```

## إعداد نقاط الخدمة

يمكن تمرير القيم التالية كخصائص Gradle محلية أو من CI، ولا تضع مفاتيح API سرية في تطبيق Android:
- `ATLAS_SEARCH_API_BASE_URL`: عنوان أساس Search API.
- `ATLAS_UPDATE_MANIFEST_URL`: عنوان بيان تحديثات التوزيعة المباشرة.

## عقد Search API

`POST /search`

طلب:
```json
{
  "query": "أريد معرفة سبب ضعف إنتاجية التربة",
  "language": "ar",
  "mode": "hybrid",
  "limit": 20
}
```

استجابة:
```json
{
  "results": [
    {
      "title": "عنوان المصدر",
      "url": "https://example.org/resource",
      "snippet": "مقتطف قصير يوضح صلة المصدر بالسؤال",
      "publisher": "الجهة الناشرة",
      "verifiedAt": "2026-11-07",
      "relevance": 0.94
    }
  ]
}
```

الخادم مسؤول عن فهم المعنى، والبحث النصي والدلالي، وترتيب النتائج، وتوثيق الناشر وتاريخ التحقق. لا يُفترض أن كل نتيجة بحث صحيحة لمجرد ظهورها.

## عقد بيان التحديث

مثال للبيان المستضاف على HTTPS:
```json
{
  "versionCode": 2,
  "versionName": "1.0.1",
  "apkUrl": "https://updates.example.org/atlas/knowledge-atlas-1.0.1.apk",
  "sha256": "64-character-hex-sha256",
  "releaseNotes": "إصلاحات وتحسينات"
}
```

يجب أن يحتفظ كل إصدار بنفس `applicationId` وأن يُوقّع بشهادة الإصدار نفسها. فحص SHA-256 يتحقق من سلامة الملف المنزّل، بينما يتحقق Android Package Installer من توافق توقيع التطبيق. التثبيت ليس صامتاً؛ يظل خاضعاً لموافقة المستخدم وإعدادات Android.

## حالة البحث من الواجهة

- البحث المحلي يفلتر مصادر Room المخزنة على الهاتف.
- زر "ابحث في الويب الأوسع" يستدعي Search API عبر HTTPS ويعرض عنوان المصدر والناشر والمقتطف وصلة النتيجة.
- إذا لم يتم ضبط ATLAS_SEARCH_API_BASE_URL، تعرض الواجهة بوضوح أن محرك البحث غير مربوط بدلاً من عرض نتائج وهمية.
- تمييز لغة الاستعلام العربية/الإنجليزية يتم مبدئياً بحسب النص؛ يبقى الفهم الدلالي وإعادة الترتيب والتحقق من الأدلة داخل الخادم.

## الكتالوج

الكتالوج الحالي يحتوي 120 سجلاً مرشحاً موزعة على 12 مجالاً. جميعها ما زالت `REVIEW_REQUIRED` و`accessType=UNKNOWN` وتاريخ التحقق فارغاً؛ لا يجوز وصفها بأنها مصادر موثقة. أضيف `tools/audit_catalog_links.py` لفحص استجابة HTTPS لكل رابط وإنتاج CSV/JSON. نجاح HTTP يثبت قابلية الوصول فقط، ولا يثبت ملكية الموقع أو جودة المحتوى أو الترخيص أو السعر أو دعم العربية. يبقى التحقق التحريري الفردي مطلوباً قبل ترقية أي سجل.

## التوزيع

- `direct`: توزيع APK خارج المتجر، مع مسار تحديث مستقل.
- `play`: مسار منفصل جاهز لتجهيز متطلبات Google Play مستقبلاً، دون صلاحية طلب تثبيت حزم APK من داخل التطبيق.

## ملاحظات أمنية

- لا تضع مفاتيح مزودي البحث في APK.
- لا تضع keystore أو كلمات المرور أو مفاتيح التوقيع في Git.
- يجب أن تكون كل خدمات البحث والتحديث عبر HTTPS.
- لا تنفذ التحديثات بصمت أو تتجاوز موافقة Android.


## خدمة البحث الخلفية

أضيفت خدمة أولية تحت `services/search_api`:
- FastAPI adapter مع SearXNG كمصدر بحث متعدد المحركات.
- تطبيع عربي وتوسعة استعلامات بقواعد قابلة للتفسير.
- إزالة التكرار، قبول روابط HTTPS فقط، وإعادة ترتيب أولية.
- تصنيف نطاقات الناشرين مع توضيح أن التصنيف ليس تحققاً من صحة الصفحة.

الخدمة منشورة على Railway عبر HTTPS، وتوجد اختبارات CI منفصلة واختبار حي للاستعداد وطلب بحث عربي. تفاصيل التشغيل والحدود في `services/search_api/README.md`.

**مهم:** النسخة الحالية ليست بحثاً دلالياً عصبياً؛ لا تستخدم embeddings أو vector database بعد. كما أن الكتالوج ما زال تجريبياً ولم يصل إلى هدف 100+ مصدر موثق.


## إصدار Release موقّع

أضيف مسار GitHub Actions منفصل لإنتاج نسخة `directRelease` والتحقق من توقيع APK باستخدام `apksigner`. لا يتم تخزين ملف التوقيع أو كلمات مروره في المستودع.

### إنشاء مفتاح الإصدار الدائم مرة واحدة على Windows

باستخدام JDK 17 أو أحدث في PowerShell:

```powershell
keytool -genkeypair -v -keystore knowledge-atlas-release.jks -alias knowledge-atlas -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=Knowledge Atlas, OU=Release, O=Knowledge Atlas, C=EG"
[Convert]::ToBase64String([IO.File]::ReadAllBytes("$PWD/knowledge-atlas-release.jks")) | Set-Clipboard
```

احتفظ بملف JKS وكلمات المرور في أماكن آمنة. فقدان المفتاح يمنع تحديثات التثبيت فوق النسخ الموقعة به، وتسريبه يعرّض هوية التطبيق للخطر. لا ترفع الملف إلى GitHub ولا ترسله في المحادثة.

في إعدادات المستودع `Settings → Secrets and variables → Actions` أضف الأسرار:
- `ATLAS_RELEASE_KEYSTORE_BASE64`: النص المنسوخ من PowerShell.
- `ATLAS_RELEASE_STORE_PASSWORD`: كلمة مرور ملف JKS.
- `ATLAS_RELEASE_KEY_ALIAS`: `knowledge-atlas`.
- `ATLAS_RELEASE_KEY_PASSWORD`: كلمة مرور المفتاح.

وأضف المتغيرات التالية عند تجهيز الاستضافة:
- `ATLAS_SEARCH_API_BASE_URL`: عنوان HTTPS الأساسي لخدمة البحث، دون `/search`.
- `ATLAS_UPDATE_MANIFEST_URL`: عنوان HTTPS لبيان التحديث.
- `ATLAS_PUBLIC_APK_URL`: رابط HTTPS عام مباشر لملف APK.

بعد حفظ الأسرار، شغّل `Actions → Signed Android Release → Run workflow` وحدد اسم الإصدار ورقم `versionCode` أكبر من آخر إصدار. يتحقق المسار من توقيع الحزمة وينتج APK وبيان تحديث وبصمة SHA-256 كـ artifact. يتوقف المسار إذا لم يكن رابط APK العام مضبوطاً.

**ما زال النشر الحي واختبار التحديث بحاجة إلى استضافة عامة عبر HTTPS لخدمة البحث وملف البيان وAPK، ثم اختبار التثبيت والترقية على هاتف Android حقيقي. لا يوجد حالياً مفتاح توقيع أو عنوان استضافة مضبوط في المشروع.**
